# Gitee PR normalized behavior snapshot

- Repository and mutation identity use the same remote URL hash, ref, commit, expected revision, approval, and idempotency fencing as other Forge adapters.
- Create, query, title/body/target update, close, and merge are supported; source ref changes require a new PR.
- Merge is always separately approved and is bound to the expected head SHA.
- Credentials are stored in Credential Manager; ordinary SQLite stores only `secret_ref` and metadata.
- Post-dispatch ambiguity is persisted as `indeterminate` and is never retried blindly.
