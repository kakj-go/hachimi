# WeCom official API contract snapshot

Retrieved: 2026-07-30T19:20:00+08:00

Official pages checked with HTTP 200:

- Access token: https://developer.work.weixin.qq.com/document/path/91039
- Department list: https://developer.work.weixin.qq.com/document/path/90208
- Department members: https://developer.work.weixin.qq.com/document/path/90200
- Send application message: https://developer.work.weixin.qq.com/document/path/90236
- Receive messages/events and encrypted callback: https://developer.work.weixin.qq.com/document/path/90930

Wire contract fixed for this implementation:

- `GET https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid=...&corpsecret=...`
- `GET /cgi-bin/department/list?access_token=...&id=...`
- `GET /cgi-bin/user/list?access_token=...&department_id=...&fetch_child=...`
- `POST /cgi-bin/message/send?access_token=...` with `touser` or `chatid`, `msgtype=text`, and `agentid` where required.
- Callback requests carry `msg_signature`, `timestamp`, `nonce` and encrypted XML. Signature verification sorts token, timestamp, nonce, and encrypted payload before SHA-1. The encrypted body uses the configured encoding AES key and is tenant-bound.

Only account/tenant identity, department/member reads, text message send, and message/event ingress are in scope. Approval, calendar, task, document and other APIs are excluded.
