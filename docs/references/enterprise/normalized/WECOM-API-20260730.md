# WeCom normalized behavior snapshot

- Credentials are a tenant-bound `corpId`, application secret, optional `agentId`, callback token, and encoding AES key stored only in Credential Manager.
- Access tokens are short-lived, cached in memory, and refreshed once on an authentication error.
- Directory reads are bounded and paged/limited by the official API.
- Outbound text messages are ledgered before dispatch and reconciled from the provider response; unknown outcomes are never reported as delivered.
- Callback ingress verifies signature, timestamp, nonce, tenant identity, event/message ID and replay window before normalization.
- The normalized route is `channel/account/peer/thread`; attachments remain metadata until an explicit fenced download.
- Rate-limit and transient server responses enter persisted exponential backoff; stable provider error codes are retained without credential or message-body leakage.
